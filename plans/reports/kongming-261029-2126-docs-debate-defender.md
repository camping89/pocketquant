# Docs debate: DEFENDER (keep what code cannot say)

Date: 2026-10-29. Branch: develop. Scope: `docs/**`, `README.md`, `CLAUDE.md`. Every claim below was checked against the working tree today; `file:line` cites are from that check.

## TL;DR

Accept the premise: a fact that one `Grep` recovers from one file must not be in a doc, and this repo proves why — four such copied facts are already wrong (`ENABLE_JOBS` is retired and raises at startup, yet seven doc lines tell the reader to set it; `sync_1m` fires at second 12, docs say 2; import-linter has 6 contracts, two docs say 8; the ERD says `_id` is a hash). But the boundary is not "LLM can trace it". It is "one file holds it". Keep four classes that no single file holds: a rejected alternative, an invariant that spans files or processes, a fact that lives outside the repo (VPS, Cloudflare, Exness venue, the other repo), and a requirement the code implements but cannot state as required. Delete the ERD and 21 of 29 journals, cut every copied number and formula from the five core docs, and keep the rest.

## Methodology: the "write it or not" test

Apply to every line of a doc, in order. The first rule that fires decides.

1. **One-file test.** If `Grep <token>` finds the fact in one source file (a constant, a schedule, a docstring, a comment, a test name), the doc line goes. Write at most a pointer `path:symbol`, and only in an index-style line. Evidence that copies rot: `README.md:102` and `docs/code-standards.md:295` say 8 contracts, `pyproject.toml:77-125` has 6; `docs/system-architecture.md:140` and `docs/project-overview-pdr.md:81` say `sync_1m` at second 2, `sync_jobs.py:737` says `second=12`; `README.md:39,47,68`, `docs/system-architecture.md:52`, `docs/deployment.md:218-221` tell the reader to set `ENABLE_JOBS=false`, `config.py:111-114` raises `ValueError("ENABLE_JOBS is retired ...")`.
2. **Number test.** A number is written only where it is born. Env defaults, schedules, bucket sizes, thresholds, counts: never in a doc. A doc may say "paced by the strictest published limit" and point to the file; it may not say "200 tokens, 20 per second" (`docs/system-architecture.md:29` vs `main_extensions.py:292`, correct today, wrong on the next tune).
3. **Single-site test.** If the WHY fits in a comment at one site, move it there and delete the doc line; `docs/code-standards.md:247-248` already allows WHY comments for races, ordering, invariants and venue quirks. Examples already done right in code: `routing_data_provider_adapter.py:43-44` (no fallback, why), `exness_session_calendar_adapter.py:9` (sessions in New York, why), `paper_broker_adapter.py:365-369` (cover-short never gated, why), `scheduler.py:3-4` (one scheduler, why), `main.py:60-63` (container set before first await, why). Those doc lines are now duplicates.
4. **Span test (keep).** If the WHY has no single site because it spans two files, two processes, two runtimes or two repos, keep it in a doc. Examples with no code home: the paper-broker accounting table and its reason (`docs/system-architecture.md:97-106`; `paper_broker_adapter.py` has no "spot", "Sharpe" or "all-in" anywhere); the scale-out limitation across `Signal`, `IStrategyService`, the broker and the position key (`docs/engine-scale-out-limitation.md:7-12`, symbols verified at `value_objects.py:18`, `paper_broker_adapter.py:344,579,602-615`); chart markers vs strategy signals across `web/` and Python (`docs/swing-pivot-key-level.md:62-73`; `engulfing.ts:63-65` links to that doc).
5. **Outside-the-repo test (keep).** A fact that lives on the VPS, in Cloudflare, in `pocketquant-config`, or in the Exness venue cannot be traced from this repo. Keep it, and mark how it was verified and when. Examples: `docs/deployment.md:56-70,80-91,135-174,243-282`; `docs/journals/2026-10-13-exness-api-spike.md:1737-1740,1754-1769`.
6. **Requirement test (keep).** Code shows what it does, not what it must do or must not do. Keep intent, non-goals and acceptance rules (`docs/project-overview-pdr.md:9-14`, "upsert; never duplicate", "closed-market minutes are not gaps", "live brokers are opt-in"). Drop the route lists under them; OpenAPI is the source.
7. **Trap test (keep).** Would an agent reading only the code draw the wrong conclusion? Keep the line if the trap spans files (rule 4) or sits outside the repo (rule 5); otherwise it is a comment (rule 3). Examples: `periods_per_year` is deprecated for session calendars (`enums.py:28-31`, already a comment: delete from docs); open shorts are marked to bid, so drawdown is overstated by spread × quantity while open (`docs/journals/2026-10-19-exness-spread-backtests.md:1954`; no comment in the broker: move to a comment or to the paper-broker section).
8. **Records test.** A journal survives only if it carries a decision or a measured external fact whose consequence is still live and is stated nowhere in code or a current doc. Git keeps the rest. A journal is never a link target from code or from a current doc.
9. **Wrong beats absent? No.** A line that fails its check is fixed or deleted in the same change. The ERD (`docs/visuals/collection-erd.mmd`) is the worst case: it looks authoritative and says four false things.

What to do instead when content is traceable: delete it; or replace with a pointer `path:symbol`; or move the WHY into a comment at the single site; or replace a count with the command that prints it (`uv run lint-imports`); or turn a claim into a test (the model: `docs/code-standards.md:168` cites `test_concurrent_add_same_triple_one_doc_one_error`, which exists at `test_subscription_repository.py:91`).

Reviewer's line-by-line checklist: (a) grep the token; found in one file → delete or pointer; (b) is it a number → delete; (c) is there one site for a comment → move; (d) spans files/processes/repos, or is a requirement, or a venue fact → keep, and cite how it was verified; (e) does the line still pass against code today → if not, fix or delete now.

## Strongest counter-argument against this position

Every WHY defended above could be a two-line comment at the site that owns it, which the comment policy already permits, and once each WHY sits beside its code the architecture doc is pure duplication plus a few cross-repo ops facts that belong in `pocketquant-config/README`, not here. A doc that must be re-verified against code on every change is a tax the three-year owner pays forever, while a comment is verified for free in the diff review; the four drifts found today are the bill for that tax.

I accept the tax argument for everything with a single site. I do not accept it for a span: there is no file where "the chart colors at 0.30 but the strategy reads config" or "Signal, broker and position key agree on one TP" can sit without a reader of the other files missing it, and the cross-repo ops facts are read by someone holding this repo, not the config repo.
