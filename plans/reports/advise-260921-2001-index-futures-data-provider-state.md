## scout-findings (verified in repo)
- Two ports in core/domain/market_data: IDataProviderPort (ABC: fetch_ohlcv(symbol, interval, n_bars) -> list[Bar], search_symbols, close) and IRealtimeQuoteProviderPort (Protocol, 9 members: connect/disconnect/subscribe/unsubscribe/run_forever/is_connected/subscription_count/subscriptions/last_tick_at). Only impl: BinanceAdapter (REST klines) + BinanceWebSocketAdapter (@aggTrade) in core/infra/binance/.
- DI binds exactly ONE IDataProviderPort (app/di/infrastructure.py get_data_provider -> BinanceAdapter) and ONE IRealtimeQuoteProviderPort (app/di/market_data.py -> BinanceWebSocketAdapter). No per-exchange routing exists; symbol is composite {CODE}:{EXCHANGE} and adapters strip the exchange as an "opaque postfix". Adding a second venue needs a routing/composite adapter keyed on the exchange suffix, or a second binding.
- Binance code-level validate_symbol regex ^[A-Z0-9]{6,12}$ would reject "ES1!" — the composite symbol regex in core/domain/symbol/entities.py (COMPOSITE_SYMBOL_RE) must be checked for "!" too.
- Sync design (engine/market_data/app_services/sync_jobs.py): sync_1m cron every minute fetches last 100 1m bars per tracked symbol via REST, upserts, then cascades 1m -> 5m/15m/1h/4h/1d in-process (UTC-aligned buckets, 1d at UTC midnight; 1w fetched natively from provider because Monday alignment). fetch_with_retry (provider_fetch.py) retries when no bar is aligned to the interval — tuned for a 24/7 venue with +2s cron offset. Futures have a daily halt (16:00–17:00 CT) and weekend closure: every minute during the halt the retry path burns 15s of budget and anomaly_log will log "no progress" streaks unless a session calendar gates the job.
- Interval.periods_per_year hardcodes 365*24*60 (crypto). Sharpe/Sortino annualization is wrong for futures (~23h/day, 5 days/week -> ~1,380 1m bars/day, ~252 sessions). Cascade 1d bucket at UTC midnight != CME settlement/session day (17:00 CT open).
- Realtime: WsSubscriptionAppService diffs tracked_symbols vs provider subscriptions every 5s; QuoteAppService.on_quote_update builds bars from tick dicts (last_price, volume delta). Known latent bug: BinanceWebSocketAdapter.subscribe() doesn't send a SUBSCRIBE frame on an open socket (handoff report 260718).
- Lineage: constants.LIMIT_TVDATAFEED_MAX_BARS = 5000 and sync_dtos cap n_bars at it; scripts/backfill/binance_bars.py docstring mentions "TradingView REST's 5000-bar cap". The project once used tvdatafeed (unofficial TradingView scraper) and migrated to Binance.
- Prod today: 3 crypto symbols (BTC/ETH/SOL USDT:BINANCE), 2y of 1m bars each (~1.05M bars/symbol), live WS, cron sync, VPS single-process. Broker adapters: paper + OKX (perp SWAP). No futures broker.
- Web SPA treats exchange as an opaque badge (parseSymbol) — composite format works for any exchange string, placeholder text says BTCUSDT:BINANCE.

## reframing-draft (v2, presented for confirmation as Q7)
problem: PocketQuant is hardwired to one 24/7 crypto venue: DI binds exactly one REST provider and one WS provider, and sync/cascade/annualization/paper-broker math assume continuous trading and price x qty units. User wants ES1!/NQ1!/YM1! (CME/CBOT continuous front-month index futures) for charts, live paper trading and higher-timeframe/forward-accumulating backtests, sourced from TradingView via tvdatafeed-or-equivalent, delivered through (a) an asset-class model driving session/annualization/contract math in the EXISTING pipeline and (b) provider resolution keyed by asset class + provider id so a 3rd/4th provider or a 2nd provider per asset class is config + one adapter.
requirements (v1):
R1 AssetClass enum on Symbol (replaces free-string asset_type), e.g. CRYPTO_SPOT, CRYPTO_PERP, INDEX_FUTURE; each class binds annualization basis and contract-spec shape; per-symbol contract values (ES 50, NQ 20, YM 5 USD/point; tick 0.25/0.25/1.0).
R1b TradingSchedule is persisted DATA stored alongside the asset class (not a futures special case; 24/7 is simply crypto's schedule): exchange local timezone (IANA), weekly session open/close, daily maintenance halt, weekend closure, holiday list hook, and session-day boundary used for 1d/1w bucketing. A future asset class (equities, forex) = new enum member + new schedule record, no new branching.
R2 Provider registry/resolver replacing single DI binding for BOTH ports: config maps asset class -> ordered provider ids (primary + fallback), optional per-symbol override; callers (sync, backfill, WS subscription manager) resolve per symbol; exchange suffix parsing stays at adapter boundary.
R3 TradingView adapter pair: IDataProviderPort (scraper get_hist, fut_contract=1 continuous, configurable bar cap, paging up to cap) and IRealtimeQuoteProviderPort (9-member Protocol; polled bar-close updates at minimum, tick push if the scraper supports it); scraper library isolated behind an internal client interface so it can be swapped.
R4 Entitlement is config: TV creds/auth token, bar cap, delay flag, provider map read via Settings from env; values live in ../pocketquant-config; nothing in repo/report.
R5 Session-aware pipeline: sync_1m/retry/anomaly gated by the symbol's session calendar; 1d/1w for INDEX_FUTURE from provider natively or session-boundary cascade (never UTC-midnight bucket); crypto path unchanged.
R6 Initial backfill of the 3 symbols to the configured cap per timeframe (1m,5m,15m,1h,4h,1d,1w); cron accumulates 1m forward.
R7 Paper broker, backtest engine, performance calculator read the asset-class spec: PnL = points x multiplier x contracts, integer contracts, per-contract commission option, session-based annualization; existing futures margin accounting kept as-is.
R8 UI: 3 symbols selectable in chart/strategy/backtest dialogs, exchange badge works, placeholder text no longer Binance-only.
R9 Tests: resolver, TV mappers (offline fixtures), session calendar, contract math, one end-to-end sync for a futures symbol; all existing crypto tests stay green.
R10 Timezone correctness across the sync pipeline: no naive datetimes cross a boundary (Mongo reads, provider mappers, schedule math); storage and arithmetic in UTC; exchange-local session times converted via zoneinfo (America/Chicago for CME) with DST handled; explicit tests for DST spring-forward/fall-back on session boundaries, holiday/half-day sessions, Sunday reopen, session spanning UTC midnight. (kongming audit findings to be merged by orchestrator.)
R11 UTC enforcement is a verified system-wide invariant (crypto included): TZ=UTC pinned in Dockerfile/compose/systemd; startup assertion that process local tz == UTC (fail fast); lint rule (ruff DTZ) + test that fails on naive datetime construction; Mongo client tz_aware=True (or boundary coercion that RAISES on naive instead of silently attaching UTC).
goals (v1): G1 ES/NQ/YM charts show fresh bars within one cron cycle during session hours; G2 a paper strategy on ES runs a full session with correct USD PnL; G3 a 1h ES backtest over the available history reports dollar PnL/Sharpe consistent with contract spec; G4 adding another provider = one adapter + one config entry, zero caller edits; G5 BTC/ETH/SOL behaviour and tests unchanged; G6 app refuses to start on a non-UTC host and the DST-boundary test suite passes.
non-goals (v1): real futures broker/live money; multi-year 1m futures history (deferred, recorded as trade-off); Databento/IBKR adapters; tick-level fidelity beyond scraper capability; modelling contract roll in paper positions; redoing margin accounting; plan-tier branching in code.
constraints: single uvicorn process (WS/scheduler singletons); ports in core/domain, adapters in core/infra, repos in core, import-linter contracts; composite {CODE}:{EXCHANGE}; creds only in ../pocketquant-config; KISS/DRY, reuse existing pipeline (no parallel futures pipeline); user accepts TradingView ToS/scraper-breakage risk and bar-cap history limit.
