# Red team: Failure Mode Analyst (flow tracer), 2026-10-28

1. Critical — Handover gate is vacuous while live is off: all 11 prod handovers run with `EXNESS_LIVE_TRADING=false`, so no Exness broker exists (`broker_factory.py:73-75`); paper `inflight_count` = 0 and paper signals run inline (`broker_port.py:23`), so `inflight=0`/no drain_timeout hold by construction; rehearsal has no subscriptions. A swallowed reconcile error leaves `_needs_snapshot` True (`exness_broker_adapter.py:631-637,467-469`) → every deploy drains 150 s. Fix: CI integration test driving real lifespan with a fake slow Exness adapter (SIGTERM mid-open → drain, release, takeover); Phase 11 requires N live-armed handovers before go-live; `inflight_count` counts only `_inflight` + `_pending_ack` (or re-triggers snapshot).
2. High — Bars closing at the boundary lose entries and paper exits: old trader checks idle at B+1 s then disarms; timer close lands at B+0.5..0.75 + lag; inline paper `_process_signal` mid-fill (`paper_broker_adapter.py:160-161`) invisible to drain; discards are DEBUG (prod INFO); old paper broker disconnects in `engine.stop()` before new connects, so a paper SL crossing that bar is unchecked; drain can release before paper fill Mongo writes land. Fix: release only after BarAppService published every bar of boundary B; count inline paper processing as in-flight; log lease/drain discards at INFO with a count in the handover row.
3. High — Exception in `on_acquired` leaves "held" lease with no renewal and no trading; health says held. Takeover >25 s arms `trading_until` already past. Fix: renew alongside `on_acquired`; wrap it (on failure: state lost, release, SIGTERM); health reports lease doc `renewed_at` age.
4. High — Grace arithmetic wrong: drain deadline starts after uvicorn graceful (10 s) + stop_worker; then `_cancel` (5 s), `stop_reconcile_loop` (5 s), `engine.stop()` gathers signal tasks with no timeout; an `openPosition` can take ~33 s (`exness_client.py:63,66,319-329`); lease renewal cancelled before `engine.stop()` and release → lease lapses while old process still connected → two writers. Fix: deadline from lifespan-shutdown start; keep renewing until after `engine.stop()` and release; bound the gather by remaining grace; ≥30 s margin or larger grace.
5. High — Lease fence checked once per signal, not before send: after the check the path waits on `_open_lock`, stored-pause read, sync loss-cap read (~2 s), order lane, resend (~33 s); `_on_lost` awaits tasks instead of cancelling. Fix: pass a deadline into `submit_order`, re-check after lock and after pacer wait right before `_send`; no resend past deadline; cancel pre-send tasks on lost.
6. High — `takeover_ms` read from never-emitted `trader.takeover_complete` (same as scope critic 2); also `handover_gap_ms` computed at end of `_take_over` includes takeover duration, so gap ≤ 2000 overrides takeover ≤ 5000. Fix: `trader.takeover handover_gap_ms` at acquire (acquire − release), `trader.takeover_complete takeover_ms` at end; consistent targets.
7. Medium — Redis seed drops the gap flag (`bar_builder_domain_service.py:118-130` `to_dict` has no gap); standby trader and probe write/delete the same `bar:current` keys every 0.2 s (`bar_app_service.py:211-236`), API SSE reads them (`:244-252`). Fix: persist gap + coverage start; only the lease holder writes/deletes `bar:current`.
8. Medium — OOM check comes after the irreversible `docker stop pocketquant-app` in the cutover (four runtimes + mongod ~1 GB cache [I] on 3 GB). Fix (within D31): record OOM count before `dc up`, re-check before `docker stop pocketquant-app`, abort with `rm -sf api worker trader` if it rose; add a probe `api` in Phase 07 so the overlap peak is measured before Deploy B.
