# Red team: Security Adversary (fact checker), 2026-10-28

Context verified by the reviewer: `camping89/pocketquant` is PUBLIC (config repo private); prod logs are console with rich tracebacks (`show_locals=True`, `setup.py:71`); VPS SSH user is root.

1. High — Phase 07 probe containers (`docker run -d --name pq-probe-*`, no `--rm`, no stop-timeout, cleanup only if the SSH session survives `sleep 600`) can be left running with prod creds and win the prod trader lease at the Deploy B cutover; Phase 08 gate counts only `pocketquant-app`; `--remove-orphans` ignores them; lease checks count owners but do not identify them. Fix: self-terminating probe (`timeout -s TERM 600`, `--stop-timeout 180`, label `pq-probe=1`), pre-`docker rm -f`, Phase 08 gate `docker ps -aq --filter label=pq-probe=1 | wc -l` = 0, lease owner hostname must equal the compose container hostname.
2. High — Public unauthenticated `GET /api/v1/admin/safeguards` (GET skipped by admin auth `admin_auth_middleware.py:23,35`; exempt from rate limit `rate_limit/middleware.py:7,39-40`) becomes a Mongo read per request (Phase 04 Task 4.1 step 8), sharing the store the fail-closed open path reads → internet flood degrades entries. Fix: exemption POST-only; GET from a ≤1 s in-process cache or token-required; CI test that a GET flood gets 429.
3. High — Roles fail open: `app_roles` default `"api,worker,trader"`, `extra="ignore"` (`config.py:44`) silently ignores the old `ENABLE_JOBS=false` opt-out in copied local `.env` files that tunnel to prod Mongo → a laptop can take the prod trader/worker lease. Fix: default `app_roles="api"` (compose sets roles explicitly); fail when `ENABLE_JOBS` is present; verify lease owner identity.
4. High — Rolling deploy has no lock: CI `cancel-in-progress: true` (`cicd.yml:13-15`) can kill a roll mid-scale; manual re-rolls are outside CI; `roll()` assumes one running copy (`old=$(dc ps -q)`, `grep -vxF`) → two copies left → every later deploy fails. Fix: `flock -n` on `/opt/pocketquant/deploy.lock`; `roll()` refuses unless exactly 1 running copy; `cancel-in-progress: false` for master.
5. Medium — `api` and `worker` inherit `EXNESS_LIVE_TRADING` and the signing key via shared `env_file`; the lease fence lives in the engine, not the client (`exness_client.py:265-266`). Fix: `EXNESS_LIVE_TRADING: "false"` in the `api` and `worker` `environment:` blocks; assert in Task 8.1 Verify.
6. Medium — Deploy paths print `docker logs --tail 50` per role into public GitHub Actions logs (`cicd.yml:237-240`) with rich `show_locals` tracebacks; "VPS versions" committed to a public repo; saved logs never pruned. Fix: write the tail to `$LOG_DIR/failed-<svc>-<ts>.log` and print only the path; keep versions in `.cache/`; `exception_formatter=structlog.dev.plain_traceback` (or `show_locals=False`); prune `*.log.gz` older than 30 days.
7. Medium — Admin token and Mongo root password on command lines (`mongosh -p`, `curl -H "X-Admin-Token: $ADMIN_TOKEN"`) in Phases 03, 06, 10, 11. Fix: Python one-liner via `get_settings()` inside the role container; `curl -H @-`.

Fact check: Phase 10 claim "logs rotate at 5 MB x 3 (`compose.prod.yml:87-91`)" FAILED (it is `10m`). Phase 01 line refs off by 1-2 (`ExnessClient` :198, `subscribe` :54, `run_forever` :73). Everything else sampled in Phases 01, 07, 08 VERIFIED.
